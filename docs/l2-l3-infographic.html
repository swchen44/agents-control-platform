📓 L2 → L3:把個人 AI 技能平台化

Background・Why・What・Key(ARCP = Agent Runtime / Control Plane)

🪜 BACKGROUND:AI 賦能五階

L0 手工作業
全部人做,沒有 AI
L1 個人賦能
各自用 ChatGPT / Claude / Codex
L2 技能可複用
提示詞/skill 整理成資產(Jarvis)
L3 流程化整合 ★現在
事件驅動、進 CI/CD/SQC 正式流程
L4 自主閉環
自跑自檢,異常才找人(未來)

人的角色:執行者 → AI 協作者/操作員/治理者;AI:個人工具 → 可驗證、可規模化的流程能力

🤔 WHY:L2→L3 會痛在哪?

① 變成黑盒子

互動模式(Claude Code/codex 看得到、能插話)→ 非互動後:看不到中間狀態、不能中途補 log/需求、不能最後把關。

② 執行環境改變

換 SDK 直連 model?CLI 自帶的 harness engineering(上下文管理)就沒了——好結果無法直接延用,又要重新 debug。

③ 部署流程重複討論

每個 agent 上 L3 都要跟公司流程再談一次 debuggability / traceability / 人機交接……N 個 agent 談 N 次,浪費。

✏️ 名詞小抄(定義)
  • daemon agent:python while loop 常駐,watch WITS/Jira、有 timer、call 其他 agent(=Assignment/poller)
  • non-interactive agent:headless(claude -p/codex exec)+ workspace + SKILLS,可 resume,context 只限該票任務
  • 溝通與 log:cross/internal 一律記在 Jira ticket + session log——短期 debug、長期餵 L4
  • WITS(CR)=QA/客戶 issue;Jira(ticket)=人與 agent 互動

💡 WHAT:三個對策(全部已落地)

① Jira 當紀錄機制debuggability・traceability
  • status 同步看板(monitor/kanban)・context id 留存 → resume
  • 人機互動:一次性表單(比切 assignee 更穩:驗格式+留 email/IP 稽核)
  • 算效率效益(KPI)・lesson learn・L4 素材:人為何介入全留 log
② 不換 SDK,直接包 CLI

rawcli 直接 spawn claude -p / codex exec ——保留 CLI 的 harness 工程;A/B/C 實測對照(事件粒度 18:1)佐證這條路。

③ 泛化成同一個平台

新 agent = 一個 profile + skill 資料夾;trace/HIL/審批/budget/門禁/KPI 全繼承,只討論一次。

🔑 KEY

「Jira 是人與 Agent 的溝通系統」——票=工作日誌;平台把黑盒子重新打開:L0–L3 四層 trace、6 態生命週期、證據型驗收,異常才找人。

✎ 1/2 — 背景與主張
ARCP・2026-08

🛠 HOW:一張票的旅程與所有細節

WITS/CR → Jira → Agent → 驗證 → 人關單(全流程已在 KP2 端到端實測)
Jira 看板同步: To Do➜In Progress=執行中➜ Pending=等人(HIL)➜ Resolve=等評分➜ Closed / 任何狀態 ➜Cancelled(cancel/安全審/交接…理由入庫)
📥 來源
WITS/CQ(CR 編號)scan job 掃描;或人開票/排程 job。
CRID 去重:harness 必擋 + REST 預濾(404=新)
🎫 Jira 開票
label = 入場券(arcp.*);description 契約:crid / prompt / email→負責人門禁
🚦 Assignment(poller)
python while loop 常駐;route/keyword 分類 → select 遞歸 triage 挑 profile;判不出→中止。審批 profile 先發審批表單(提交即放行)
🗂 Workspace 佈建
template + SKILLS + TICKET.md(任務簡報);安全掃描(prompt injection→擋下交人審)
🤖 Non-interactive Agent
claude -p / codex exec(headless);internal loop:attempt→證據 verify(檔案/命令/CI)→敗則帶證據重試;crash→resume(context id)不重工
📦 交付 + 人關單
OUTPUT.json→票上交付物(報告/patch/Gerrit 連結);評分表單(0–10 必填)→close / 續跑 / 換手
👷 領域 Coding Agents(scan 找問題・fix 有標準答案・dev 沒有) → 每個=一個 profile + skill 資料夾,平台機制全繼承;內網落地時照 KP2 已驗證的模式建即可
scan(發 CR,去重不重發): SecurityQualityMemslim fix(CR→分析報告+patch+UT/IT 報告): FuzzCoverityMemslimPhy 回歸Performance dev: 專業 Dev(spec→FRD/SRS/SDS→code)

skill 內容 = 看 log・控制設備/儀器・夾版本・Auto-UT 派單・x86/wut 實驗・preflight/CI/CD——把做法拆成 flow skill + 共同 skill,大任務開 sub-agent(跨 agent overhead 太高,sub-agent 解 context)。

🔁 兩種迴圈

internal:agent 自己的 attempt/verify 迴圈(監 CI 結果、分類、再試)。
cross-agent:票留言/表單 → Assignment 重新派工:retry・同票 next 換手・跨票 base 交接(帶 BASE_ 脈絡開新票)。CI/CD 監看採 Jira 引擎定期喚醒(你偏好的方案)而非 agent 內 timer。

🛡 護欄(黑盒子的把手)

HIL 表單:審批・補資訊・hold 中斷給新指示・評分;負責人 email 門禁(+管理者豁免、IP 稽核);budget 6 層上限(soft 自助增額);併發閘門+排隊;TICKET.md 安全掃描(fail-closed)。

🔎 可觀測(L0–L3)

journal 事件 50 種・attempt 封套・agent 對話全文・transcript 打包;dashboard:全域時間軸(粗看)+ 單票駕駛艙(細看);KPI 北極星 = First-pass close rate + 制衡指標(人評/打回率/UNKNOWN)防「調鬆驗收」作弊;A/B 對照。

🔮 L4(未來)

Evolution Agent 讀 ticket/session log/人類介入原因 → 自己改 skill、補實驗——素材今天已經全在庫裡。

😊 Normal flow

改碼 → 觸發上碼/preflight(狀態持續更新 Jira)→ 完成 → Jira 通知人 review + submit → 評分表單 close(或 profile 設 auto_close 全自動)。

😰 Except flow

需要人決定 → 票轉 Pending 發表單 → 人下指示(提交)→ Assignment 重新喚起 agent,從 resume id 讀回之前 context 繼續——不重工。卡死/斷線:watchdog killpg→resume;超限:budget 擋下→自助增額。
